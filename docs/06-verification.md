# 06 · 起服后检查与验证

## `tp8_after.sh` 自动做五件事

1. **ARMED 核对**：容器日志里每类适配器的 `ARMED` 行与期望清单（`EXPECT_ARMED`）逐条比对，缺一条报 MISSING；
2. **八台清点**：`armed/own/refuse` 计数、HiCache 淘汰器状态（cap/watermark/现有文件数与字节）、本机缓存文件数、宿主可用内存；
3. **锁频复核**：八台 `gb10-clock-cap` active；
4. **暖机**：长提示探针（42 万 token 级 prefill）+ 两路 524k 解码交错，确认无 >1.5s 停顿；
5. **健康双口**：head 本机 `:8888/health` 与管理口 `http://<head-mgmt>:8888/health` 各 200。

全部通过后写 `TP8_UP_DONE`；起服脚本轮询到它才收尾。

## 判读要点

- `refuse=0`：出现 `refusing to arm / not the MLA storage owner` 计数非零 = 本地副本配置没生效，查 `DSV41_HICACHE_LOCAL_REPLICA`；
- `avail`（宿主可用内存）：起服后基线一般 29–37 GB/台；低于 ~6.5 GB 会触发引擎内部缓存回收，频繁回收说明池子配大了；
- 暖机交错最长间隔：健康线 1.5s 内；超线先查是不是有第三方请求同时进门。

## 压测档（sparkDash，可选但换配置必做）

| 档 | 内容 | 现役参考线 |
|---|---|---|
| 冷 prefill 三档 | 131k / 262k / 524k，N=3 取中位 | 6,542 / 6,511 / 5,834 tok/s |
| 代码 C1/C4 | 代码语料补全两档 | 203 / 399 tok/s |
| 散文 C1/C4/C6 | 自然语文本两/六档 | 111 / 248 / 284 tok/s |
| KV 池 | 实测池大小 | 8,000,000± |

多会话稳定性：4 路并发反复涨上下文（至 47 万），24 轮 0 报错、解码最长间隔 <1.1s、调度器 0 异常。

## 真实生成探针（最后一手）

压测全绿后，用真实客户端发一条实际请求（非 /health）确认首 token 正常（参考 0.25s）。**「健康 200」不等于「能生成」**——/health 不跑生成的配置下尤其如此。
